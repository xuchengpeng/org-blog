* Emacs

** 当前 elisp 文件的目录

#+begin_src
(file-name-directory (or load-file-name buffer-file-name default-directory))
#+end_src

通过以上代码可以获取当前 elisp 文件的目录， ~load-file-name~ 为通过参数 ~--load~ 或 ~--script~ 运行文件时传入， ~buffer-file-name~ 为当前 Buffer 对应的文件， ~default-directory~ 为当前 Buffer 的默认目录。

** Org 导出文件名

在将 Org 导出为 HTMl 或 PDF 的文件时，导出的文件名默认和当前文件相同，仅修改对应后端的后缀，可以通过 ~EXPORT_FILE_NAME~ 来指定导出的文件名，比如在 Org 文件头部添加 ~#+EXPORT_FILE_NAME: README~ 后，再将 Org 文件导出为 HTML 时文件名就是 README.html 。

** Typescript

Typescript v7 发布了，使用 Go 语言编写，并且内置完成对 LSP 的支持，可以直接替换 typescript-language-server 了。

在使用 Eglot 作为客户端时，需要配置一下 eglot-server-programs 变量，可以使用本地变量进行设置，如本项目的配置如下：

#+begin_src emacs-lisp
((nil . ((css-indent-offset . 2)
         (js-indent-level . 2)
         (eglot-server-programs . (((css-mode css-ts-mode) . ("vscode-css-language-server" "--stdio"))
                                   (((js-mode :language-id "javascript")
                                     (js-ts-mode :language-id "javascript")
                                     (tsx-ts-mode :language-id "typescriptreact")
                                     (typescript-ts-mode :language-id "typescript")
                                     (typescript-mode :language-id "typescript"))
                                    . ("tsc" "--lsp" "--stdio"))
                                   ((js-json-mode json-mode json-ts-mode jsonc-mode)
                                    . ("vscode-json-language-server" "--stdio"))
                                   (org-mode . ("harper-ls" "--stdio")))))))
#+end_src

** Git 提交前检查状态

在脚本中进行自动 Git 提交前，需要判定仓库是否真正有变化，否则 git commit 的时候就会报错，可以使用 ~git status --porcelain~ 来进行检查，仓库无变化时返回为空，有变化时返回的字符串也是在脚本中非常容易解析的。

#+begin_src shell
if [[ -n "$(git status --porcelain)" ]]; then
  git add .
  git commit -m "new commit"
  git push origin main
else
  echo "nothing to commit"
fi
#+end_src

** /dev/null

在 Linux 的脚本命令中，经常看到一条命令后有 ~2>/dev/null~ ，这个意思是将命令运行产生的标准错误[fn:stderr]输出丢弃，不显示在屏幕上。 ~>~ 是重定向符号，表示把命令的输出发送到后面的位置， ~/dev/null~ 为重定向的位置，是一个特殊的空设备文件，所有写入的数据都会直接被丢弃，同时返回写入成功的状态。

其他常见的类似写法， ~>/dev/null~ 表示丢弃标准输出，标准错误信息仍然会显示在屏幕上， ~>/dev/null 2>&1~ 表示先将标准输出丢弃，再把标准错误信息重定向到标准输出所在的位置，此时标准输出和标准错误全部都丢弃。
